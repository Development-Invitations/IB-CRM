## 1. Согласованный стек

| Слой | Технология | Причина |
|---|---|---|
| Desktop-приложение | **Tauri 2 (Rust)** | ~3-10 МБ вместо 100+ МБ у Electron, меньше RAM, использует системный WebView; заменили Electron в v0.1.0 после сравнения |
| Frontend | React + TypeScript + Vite | быстро, без ожидания, богатая экосистема; код почти не изменился при переходе с Electron |
| Backend (план) | Node.js + NestJS | модульность 1-в-1 ложится на модули CRM |
| БД (план, сервер) | PostgreSQL | целевая схема — `docs/db/schema.sql` |
| БД (сейчас, offline v0.1.0) | SQLite (rusqlite, из Rust-ядра) | не требует сервера для первого теста |
| Real-time (план) | Socket.io / WebSocket | чаты в проектах, уведомления |
| Очереди/кэш (план) | Redis | движок авто-распределения задач |
| Авто-обновление приложения | `tauri-plugin-updater` — подключён и работает технически (v0.1.1), не активен без реального ключа подписи и опубликованных релизов | подтягивание новых версий с сервера/Git; у Tauri эта механика продумана лучше для приватных репозиториев, чем electron-updater "из коробки" |
| Иконки UI | lucide-react | чистые, ложатся на палитру логотипа |
| Иконка приложения | генерируется из `src-tauri/icons-source/logo.png` командой `npm run tauri:icon` | официальный инструмент Tauri, сам режет под все размеры/платформы |

> **Почему ушли с Electron:** тот же UI на React/Vite, но заметно легче установщик,
> ниже расход RAM, встроенная модель авто-обновления удобнее для приватного репозитория.
> Backend-логика (`electron/db.js` с better-sqlite3) переписана на Rust (`src-tauri/src/db.rs`
> с rusqlite) — SQL-запросы и структура таблиц идентичны, просто на другом языке.

## 4. Полная схема БД (целевая, для серверной версии)

Файл: `docs/db/schema.sql` (PostgreSQL). Покрывает все модули из таблицы выше.
В offline-прототипе v0.1.0 используется урезанная SQLite-версия только с таблицами
`employees` и `app_meta` (см. `electron/db.js`) — по мере появления сервера будет заменена.

## 5. Ключевые архитектурные решения (зафиксированы, не пересматривать без причины)

1. Регистрация сотрудника — только логин+пароль, без подтверждения почты; остальной
   профиль дозаполняется самим сотрудником в личном кабинете.
2. Права выдаются точечно через `employee_permissions`, а не жёстко зашиты в роль —
   админ может делегировать право "управлять должностями" одному или нескольким людям.
3. Передача "главенства" над проектом фиксируется историей (`project_ownership_transfers`),
   а не просто перезаписывает поле.
4. Авто- и ручное распределение задач — одна таблица `task_assignments`, разница только
   в `assignment_type` и наличии/отсутствии `assigned_by`.
5. Desktop-клиент на **Tauri** (Rust-ядро), а не веб-приложение в браузере — так как нужна
   установка "приложения" с сервера и авто-обновления, что явно требовалось. Изначально
   собрали прототип на Electron, но по запросу пользователя (нужнее лёгкий/современный вариант)
   перешли на Tauri — фронтенд на React сохранён почти без изменений, поменялось только ядро.
6. v0.1.0 сознательно офлайн (без сервера) — по прямому запросу, чтобы можно было
   протестировать базовый каркас до того, как поднимать бэкенд/сервер.

## 7. Журнал изменений

### v0.1.0 — offline-прототип, Tauri-версия (текущая)
- Инициализирован репозиторий, структура **Tauri 2 (Rust) + React + Vite + TypeScript**.
- Первая сборка была на Electron — по запросу пользователя пересобрана на Tauri:
  `electron/main.js` + `electron/db.js` (Node.js + better-sqlite3) заменены на
  `src-tauri/src/main.rs` + `src-tauri/src/db.rs` (Rust + rusqlite), логика и схема идентичны.
  Фронтенд почти не тронут — только `window.api.*` заменено на `src/lib/api.ts` (обёртка над `invoke`).
- Реализован первый запуск: создание администратора локально (SQLite, без сервера).
- Реализован вход по логину/паролю, чекбокс "запомнить меня" (UI, логика — заглушка).
- Каркас кабинета: сайдбар со всеми будущими модулями (помечены "скоро"), переключатель
  темы тёмная/светлая на палитре логотипа.
- Подключён исходник лого (`src-tauri/icons-source/logo.png`) для генерации иконки приложения
  через штатный `tauri icon`.
- Спроектирована и сохранена полная целевая схема PostgreSQL под все модули (`docs/db/schema.sql`).
- Итоговый зафиксированный стек: Tauri (Rust) + React + NestJS (план) + PostgreSQL (план) + Redis (план) + Socket.io (план).

### Фикс: недостающие иконки блокировали Windows-сборку
- При первом реальном запуске `tauri dev` сборка падала на этапе `build.rs`:
  `icons/icon.ico` not found — конфиг уже ссылался на иконки, которых физически не было
  (был только исходник в `icons-source/`).
- Сгенерировал набор `32x32.png`, `128x128.png`, `128x128@2x.png`, `icon.png`, `icon.ico`
  прямо из `logo.png` и положил в `src-tauri/icons/`.
- Убрал `icon.icns` из `tauri.conf.json` — нужен только для macOS-сборки, которой пока нет;
  когда дойдём до Mac-версии, надо будет сгенерировать через `npm run tauri:icon` на Mac
  (там есть системный `iconutil`, которого нет на этой машине) или через отдельный конвертер.

### Топбар, иконки, страница настроек, реальная смена пароля
- Добавлен `lucide-react`, иконки модулей в сайдбаре (Users, Building2, Contact, FolderKanban,
  FileText, MessageSquare, Cake, Server).
- Добавлен топбар (`src/components/Topbar.tsx`): заголовок-приветствие + иконка уведомлений
  (колокольчик, пока без реальных данных — UI и поведение готовы, бэкенд появится вместе с
  регламентами/проектами) + иконка настроек, ведущая на `/dashboard/settings`.
- `Dashboard.tsx` переведён на вложенные роуты (`/dashboard` = Home, `/dashboard/settings` = Settings).
- Новая страница `src/pages/Settings.tsx`: переключатель темы (перенесён из сайдбара), заглушка
  выбора языка, блок аккаунта (логин, ID), и **рабочая форма смены пароля**.
- На Rust-стороне добавлена команда `change_password` (`src-tauri/src/db.rs` + `main.rs`):
  проверяет текущий пароль через bcrypt, обновляет `password_hash` и `password_changed_at`.
  Для этого в локальную SQLite-схему добавлена колонка `password_changed_at` (её не было в
  первой офлайн-версии).

### Фикс иконки, водяной знак, нормальный авто-вход, кастомные select/checkbox
- **Иконка приложения выглядела мелкой в панели задач** — исходное лого занимало только
  ~35-40% квадратного canvas (много прозрачных полей). Обрезал по границе непрозрачных
  пикселей и пересобрал под заполнение ~80% (стандарт для app-иконок), пересохранил как
  новый мастер `src-tauri/icons-source/logo.png` и весь набор `src-tauri/icons/`.
- Тот же обрезанный логотип используется как **водяной знак на фоне контента**
  (`public/brand/logo-mark.png`, CSS `.content::before`, opacity ~0.05-0.08) — красиво,
  не мешает читать текст.
- **Автовход был реализован неправильно**: раньше вся сессия сотрудника сохранялась в
  localStorage и должна была обходить экран логина целиком — на практике вело себя
  нестабильно в Tauri webview (человек снова и снова видел пустой логин/пароль).
  Переделал строго по исходному ТЗ: `src/lib/session.ts` запоминает **только логин**
  (не пароль, не сессию), при следующем запуске поле логина на экране входа
  подставляется автоматически, пароль спрашивается всегда. `App.tsx` больше не читает
  и не пишет полную сессию в localStorage.
- Добавлены переиспользуемые компоненты `src/components/Checkbox.tsx` и
  `src/components/Select.tsx` — стилизованы под палитру логотипа (тёмно-синий/золотой),
  заменили нативный чекбокс "запомнить меня" на Login и `<select>` языка в Settings.

### Мультиязычность (RU / UZ-латиница / UZ-кириллица)
- Добавлена полноценная система переводов `src/lib/i18n/` (`index.tsx` — контекст `LocaleProvider`
  + хук `useLocale()` с функцией `t('namespace.key', {vars})`; `translations.ts` — словари
  с вложенными ключами по разделам: `common`, `firstRun`, `login`, `sidebar`, `topbar`, `home`,
  `settings`).
- Весь видимый текст интерфейса переведён на **3 языка**: русский, узбекский на латинице,
  узбекский на кириллице (переключатель в Настройках → Язык, реализован на кастомном `Select`).
  Выбор языка сохраняется в localStorage (`ib-crm-locale`) и применяется сразу, без перезапуска.

### v0.1.8 — багфиксы после локального тестирования 0.1.7 перед публикацией
Пользователь тестировал 0.1.7 локально перед заливкой на GitHub и обнаружил 4 проблемы.
Версия поднята до 0.1.8 (та же предрелизная проверка, ещё не опубликовано).

- **Приложение "не закрывалось" по крестику** — реальная причина: обработчик закрытия окна
  в `App.tsx` использовал `getCurrentWindow().destroy()` после записи выхода
  (`api.recordLogout`). `destroy()` в некоторых случаях лишь скрывает окно, не завершая сам
  процесс — он продолжает висеть в фоне невидимым. Заменил на `exit(0)` из
  `@tauri-apps/plugin-process` (тот же пакет уже использовался для `relaunch()` после
  обновления, так что доступность гарантирована) — это по-настоящему завершает процесс.
  Заодно обернул `api.recordLogout` в `Promise.race` с таймаутом 1 секунда — если Rust-команда
  зависнет по любой причине, закрытие окна всё равно произойдёт, а не будет ждать вечно.
- **Уведомления о заявках приходили только после перезагрузки** — `Topbar.tsx` грузил список
  уведомлений один раз при монтировании и больше никогда не обновлял, пока компонент не
  перемонтируется (переход по страницам). Добавил `setInterval` на 10 секунд + принудительное
  обновление списка при каждом клике на колокольчик (перед открытием панели) — руководитель
  или админ теперь видят новую заявку в течение 10 секунд без необходимости что-либо
  перезагружать.
- **Не было возможности убрать сотрудника из подразделения** — только добавить/перевести.
  Добавил кнопку (иконка ×) рядом с каждым сотрудником в списке состава подразделения
  (`Departments.tsx`, только у админа) — `handleRemoveMember` сбрасывает `department_id` и
  заодно `manager_id` (руководитель, автоподставленный из главы подразделения, тоже больше
  не актуален, раз человек ушёл из отдела).
- **Автообновление перезапускало приложение мгновенно, без единого сообщения** — выглядело
  так, будто программа просто вылетела, а не завершила обновление. Убрал `await relaunch()`
  из `install()` в `src/lib/updater.ts`, вынес в отдельную экспортируемую функцию
  `restartApp()`. Оба места, где происходит установка (`UpdateNotifier.tsx` — автоматическое
  уведомление, и `UpdatesButton.tsx` — ручная кнопка "Проверить обновления"), теперь после
  завершения загрузки на 1.8 секунды показывают состояние "Готово!" (зелёная иконка +
  анимация появления) и только потом вызывают `restartApp()`.
- **Полный аудит на баги** — прогнал: 0 отсутствующих ключей перевода на все 3 языка;
  баланс скобок сошёлся во всех `.ts`/`.tsx`/`.css`/`.rs` файлах; отдельно проверил на
  повторение прошлой ошибки (задвоенные объявления переменных в Rust) — чисто; впервые
  сверил **полное соответствие** списка команд между `api.ts` (`invoke(...)`) и
  `main.rs` (`invoke_handler`) в обе стороны скриптом — ни одной лишней или отсутствующей
  команды. Эту сверку стоит гонять и впредь при больших правках Rust-слоя — раньше такие
  расхождения (как в прошлый раз с `deputy_employee_id`) находились только руками.
